How I Think

My Development Approach

01

Domain First

Railway RDSO specs, OCPP protocol, or BLE packet framing - I dig into the domain before writing a line of code. Wrong mental model = wrong architecture.

02

Schema Before API

I design normalized relational schemas (40–60+ tables) before writing a single endpoint. Data shapes everything - get it wrong and you pay forever.

03

Clean Boundaries

Use cases, repositories, services, data sources - clear layers that let me swap implementations without rippling changes across the whole codebase.

04

Profile, Then Optimize

I don't guess at bottlenecks. I profile. Trigger-maintained aggregation tables, batch parallel queries for 1M+ record exports, <10ms concurrent render loops - all measured, not assumed.

05

Ship & Own It

I don't hand off halfway through. Mobile app, web dashboard, API, database - I'm accountable for the entire system running correctly in production, not just in staging.
